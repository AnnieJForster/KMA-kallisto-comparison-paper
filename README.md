# KMA–kallisto algorithm comparison

Code for *Differential sensitivity of k-mer based identification tools using closely
related database sequences affects relative abundance estimation*, by Annie J.
Forster, Michael Payne, Rebecca Rockett, Cameron Webb, and Tanya Golubchik.

This repository compares algorithm performance for read identification and
relative abundance estimation with KMA and kallisto. It uses synthetic sequence
simulations and mosquito COX1 and SARS-CoV-2 sequence datasets.

## Reproduce the manuscript figures

Use Python 3.10 or newer. From the repository root:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m analysis.simulations.figures
python -m analysis.real_data.figures
```

The scripts write 16 PDFs to `figures/`, named by manuscript figure and panel.

For figure generation, required tables and reference sets can be downloaded from Zenodo (10.5281/zenodo.23328846).
They use result tables and reference sets, so no raw reads or external
assignment tools are needed.

## Run the simulations

The six experiments described in the manuscript are available through the
original processing functions, with a small command-line entry point:

```sh
python -m analysis.simulations.main --output-dir results/simulations/new_run
```

Defaults match the manuscript: 10 simulation sets, 10,000 bp, 1,000 read pairs,
the original uneven mutation schedule from 1 to 2,000, and 250 mutations for the
proportion experiment. KMA, kallisto, and wgsim must be on PATH. Choose a new
output directory for each run. Generated reads and references are retained.

For a small development run:

```sh
python -m analysis.simulations.main --output-dir results/simulations/small_run \
  --simulation-sets 1 --mutation-counts 1 10 --experiments ID_M ID_D
```

Simulations to generate Figure 2 involve nested mutation loops and takes considerably
longer than the others. Original stochastic behavior is preserved; new runs
will not recreate the included historical tables exactly. To plot new runs,
change the input directories and replicate ranges in `analysis/simulations/figures.py`.

## Repository contents

```text
analysis/
  simulations/   # Six simulation scenarios and Figures 1–5, S2
  real_data/     # Read preprocessing, mixture analysis, and Figures 6–7
  shared/        # K-mer, distance, and mosquito label helpers
config/          # Sample selections and read paths
data/           # Simulation tables and real-data figure inputs - available from Zenodo
```

`config/samples.json` contains the original sample selection with relative read
paths. If desired, read data can be downloaded from ENA. `config/samples.updated.json` contains aligned SARS-CoV-2 inputs and the
revised mosquito selection, with two mosquito samples recorded under `excluded`.
The optional alignment helper writes aligned R1/R2 files to `results/align` by
default and records those paths in the updated sample JSON.

## Real-data mixture analysis

Provide the reads at the paths in the configuration, or copy the configuration
into an ignored `config/*.local.json` file and edit its paths. Relative paths are
resolved from the working directory, so run from the repository root.

```sh
python -m analysis.real_data.main --samples config/samples.updated.json \
  --mosquito-fasta /path/to/mosquito-references.fasta \
  --covid-fasta /path/to/sars-cov2-references.fasta \
  --output-dir results/
```

 The optional alignment and
k-mer stages also require minimap2, samtools, bedtools, and Jellyfish; the k-mer
helper currently uses macOS `gzcat`. Simulations additionally use wgsim. Mash distance is calculated in Python from
full k-mer sets, without calling the Mash executable.
The manuscript reports kallisto 0.51.0, KMA 1.6.8, wgsim 0.3.1-r13, and NumPy 2.3.4.
See the release notes for discrepancies to resolve.

Raw reads are not bundled. The reference sets and final real-data mixture
summary tables used for the figures are available from Zenodo.
The SARS-CoV-2 accession identifiers are retained in the sample filenames.
